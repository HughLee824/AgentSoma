# AgentSoma v0.1 实现计划

状态：2026-09-05，第 1–7 项已通过验证：CoreDevice 原生通信、Swift CLI / 会话宿主、观察与引用、设备动作与目标校验、设备/App 发现和 agent 完整调用、独立 Runner 构建与首次接入，以及 stdin 与独立 Return。临时 App 白名单已移除，build-runner 为 connect 生成签名产物。见 [首次接入](onboarding.md)、[完整调用验收](discovery.md)、[动作验收](actions.md)、[观察验收](observations.md)、[通信报告](../spikes/ios-xctest/NATIVE.md) 与 [宿主验收](session-host.md)。

## 已确认的边界

AgentSoma 为外部 agent 提供真实 iPhone 的观察与动作。自然语言理解、任务规划、测试判断和恢复决策由调用 agent 负责。

调用结构为：`Agent → agentsoma CLI → Swift 宿主进程 → CoreDevice 通道 → 薄 XCTest Runner`。

- Mac 端管理会话、AX 精简、快照、短引用、失效规则与命令串行化；Runner 封装必要设备原语及执行前提检查，保留未来移除它的可能。
- CLI 与宿主由同一 Swift 程序提供；使用 ArgumentParser、Foundation 进程管理、Unix 域套接字和 JSON 本地消息。
- 默认空闲 30 分钟回收，可调整；有效会话命令完成后续期，执行中的命令不算空闲，内部保活不续期。
- 默认观察为截图与确定性生成的紧凑 AX 文本；详情读取同一份快照。动作派发后旧引用失效，unknown 不自动重发。
- v0.1 接受 Mac/Xcode 与首次签名配置，尽量少依赖第三方工具。iproxy、pymobiledevice3 等实验工具不自动成为产品依赖。

接口细节以 [接口草案](agent-interface.md) 为准；决策依据见 [架构记录](cli-vs-mcp.md) 与 [alignment.md](../alignment.md)。

## 开工条件

当前没有必须先由用户补充、会阻塞首个开发任务的需求问题。产品职责、宿主与 Runner 的边界、主要接口语义、生命周期和技术栈已经足够明确。

- CoreDevice 到薄 Runner 的直连和最小 CLI / 宿主已通过验证：连接就绪后返回、跨命令复用、设备互斥、显式断开和缩短时间的空闲回收均有证据。宿主观察、引用、inspect、设备动作、目标校验、发现入口与完整调用验收也已通过；独立 Runner 构建与既有 Xcode 签名条件下的首次安装也已通过。
- 其余参数、消息格式、AX 输出预算、依赖版本等按已确认语义选择最小实现，并通过可运行结果和针对性检查收敛，无需逐项增加开工前确认。
- 项目许可证与正式系统支持范围在公开发布前确定，不阻塞当前环境上的开发。若验证发现需要改变产品职责、增加额外设备工具或提高系统前提，再带具体证据重新对齐。

| 3（已通过） | 实现宿主观察与引用 | 18 项本地测试覆盖确定性精简、输出预算与源截断区分、inspect 读取原快照、引用失效及缓存清理。真机独立 CLI 验证四次观察、详情不请求 Runner、open 后引用失效、缓存淘汰与正常退出；XCTest 1/0/0。真实按引用执行的目标校验归第 4 项。见 [证据](observations.md)。 |
| 4（已通过） | 接通薄 Runner 的动作与结果 | 24 项本地测试通过；真机 39 次 CLI 调用、17 次观察验证引用点击、滑动、光标插入、Unicode 替换与清空、无自动提交、目标自行变化和歧义拒绝、坐标点击及受控 WebView。执行事实支持三态结果，unknown 不重发；持续会话与修正后的独立输入 XCTest 各 1/0/0。见 [证据](actions.md)。 |
| 5（已通过） | 验收 agent 的完整调用过程 | 29 项本地测试通过。真机 26 次独立 CLI 调用、5 次观察完成发现设备/187 个 App、连接、打开、读图、Fixture 点击与计数核对、Settings → General 导航、断开与清理。安装检查失败在派发前拒绝并保留引用；App 白名单已移除，始终复用同一 Runner，XCTest 1/0/0。见 [证据](discovery.md)。 |
| 6（已通过） | 完成独立 Runner 构建与首次接入 | 33 项本地测试通过。两次独立签名构建成功，缺少团队的构建明确失败；干净 Runner 源码副本从包含空格的路径构建，不依赖 XcodeGen 或 Fixture。真机首次安装默认 Runner，8 次 CLI 调用完成连接、观察、引用导航与清理，XCTest 1/0/0。见 [证据](onboarding.md)。 |
| 7（已通过） | 补齐 stdin 输入与独立 Return | 38 项本地测试、9 项 CLI 边界检查通过。真机 20 次 CLI 调用、6 次观察确认原文替换/追加、空输入清空、无自动提交，以及独立 Return 后提交计数 0 → 1；5 次预期拒绝均未派发。复用同一 Runner，XCTest 1/0/0，资源正常清理。见 [证据](actions.md#stdin-与-return-补充验收)。 |

第 6 项在既有签名环境中验证首次安装，并非全新 Mac 或免 Xcode 接入。

第 1 项使用独立的新通信证据，没有借用以前经过 iproxy 的结果。第 2 项在同一条原生链路上实现宿主生命周期：默认值为 1800 秒，实际回收以缩短为 8 秒的真机会话验证，没有等待完整 30 分钟。Runner 在宿主管理模式下不再使用实验的固定 900 秒上限，旧探针模式仍保留该上限。

实现检查应围绕具体风险：原生通信需要真机证据；格式化、引用和计时规则尽量用本地样本与受控条件验证。原有物理重连、锁屏恢复和更广 App/OS 覆盖仍保持较低优先级。

## 实现时收敛的细节

本地 IPC 已采用版本化 JSON 行，一次连接承载一条请求 / 响应；ArgumentParser 已锁定 1.5.0。生命周期和动作输出 JSON；动作依据 Runner 执行事实返回三态结果。观察输出、AX 预算、快照缓存及引用失效已实现，工程默认值见 [观察验收](observations.md)。坐标、滑动参数和实时目标定位已落地，输入采用 4096 UTF-8 字节上限、拒绝换行/控制键，见 [动作契约](actions.md)。设备/App 发现已实现，App 查询按名称/bundle ID 筛选，每页 50 项，见 [发现契约](discovery.md)。stdin 和独立 Return 已完成，仍采用 4096 字节单行文本边界；其他按键和更长/多行文本尚未扩展。当前 build-runner 返回实际签名产物路径供 connect 使用；独立工程无需 XcodeGen 或 Fixture，首次安装与连接已通过，见 [接入说明](onboarding.md)。改变产品边界、引入额外设备工具或提高系统前提时，需要重新对齐。

公开发布前还需确定项目许可证与实际支持的系统范围。当前真机证据来自 macOS 15.0.1、Xcode 16.0、iOS 26.6；免 Xcode 安装及未来完全移除 Runner 均没有因此成为已验证能力。
