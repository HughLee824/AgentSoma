# AgentSoma v0.1 实现计划

状态：2026-09-05，第 1 项 CoreDevice 原生通信和第 2 项最小 Swift CLI / 会话宿主已通过验证。当前提供 connect、status、open、disconnect；下一项是宿主观察与引用。见 [通信报告](../spikes/ios-xctest/NATIVE.md) 与 [宿主验收](session-host.md)。

## 已确认的边界

AgentSoma 为外部 agent 提供真实 iPhone 的观察与动作。自然语言理解、任务规划、测试判断和恢复决策由调用 agent 负责。

调用结构为：`Agent → agentsoma CLI → Swift 宿主进程 → CoreDevice 通道 → 薄 XCTest Runner`。

- Mac 端管理会话、AX 精简、快照、短引用、失效规则与命令串行化；Runner 封装必要设备原语及执行前提检查，保留未来移除它的可能。
- CLI 与宿主由同一 Swift 程序提供；使用 ArgumentParser、Foundation 进程管理、Unix 域套接字和 JSON 本地消息。
- 默认空闲 30 分钟回收，可调整；有效会话命令完成后续期，执行中的命令不算空闲，内部保活不续期。
- 默认观察为截图与确定性生成的紧凑 AX 文本；详情读取同一份快照。动作派发后旧引用失效，unknown 不自动重发。
- v0.1 接受 Mac/Xcode 与首次签名配置，尽量少依赖第三方工具。iproxy、pymobiledevice3 等实验工具不自动成为产品依赖。

接口细节以 [接口草案](agent-interface.md) 为准；决策依据见 [架构记录](cli-vs-mcp.md) 与 [alignment.md](../alignment.md)。

## 开工条件

当前没有必须先由用户补充、会阻塞首个开发任务的需求问题。产品职责、宿主与 Runner 的边界、主要接口语义、生命周期和技术栈已经足够明确。

- CoreDevice 到薄 Runner 的直连和最小 CLI / 宿主已通过验证：连接就绪后返回、跨命令复用、设备互斥、显式断开和缩短时间的空闲回收均有证据。下一项是宿主观察与引用。
- 其余参数、消息格式、AX 输出预算、依赖版本等按已确认语义选择最小实现，并通过可运行结果和针对性检查收敛，无需逐项增加开工前确认。
- 项目许可证与正式系统支持范围在公开发布前确定，不阻塞当前环境上的开发。若验证发现需要改变产品职责、增加额外设备工具或提高系统前提，再带具体证据重新对齐。

## 实现顺序与验收

| 顺序 | 工作 | 验收条件 |
| --- | --- | --- |
| 1（已通过） | 验证 CoreDevice 到薄 Runner 的原生通信 | 使用 Apple 设备工具建立和发现通道，Mac 原生客户端访问适配后的 Runner 端口；7 次独立请求复用同一 Runner，约 60 秒命令间隔后仍可访问，显式结束后本会话进程退出。链路不借助 iproxy 或 pymobiledevice3。见 [证据](../spikes/ios-xctest/NATIVE.md)。 |
| 2（已通过） | 实现最小 Swift CLI 与会话宿主 | 真机 connect 返回后独立 CLI 复用原宿主 / Runner；显式断开、8 秒受控空闲回收、open 续期、status 健康检查不续期、同设备别名重复连接拒绝均通过。10 项本地测试覆盖 Unix IPC、执行中 / 排队命令、清理与 unknown 不重发。见 [验收报告](session-host.md)。 |
| 3 | 实现宿主观察与引用 | 用已有 AX 样本验证确定性精简、必要内容保留、超预算时的明确提示；inspect 读取原快照。派发动作、未知结果及会话失效后均不能继续使用失效引用。源数据未采集到的内容不能伪装成可展开。 |
| 4 | 接通薄 Runner 的动作与结果 | 点击、滑动、插入与整段替换符合接口语义；输入不自动提交，歧义目标明确拒绝。后端提供足够执行事实，宿主能区分 completed / not_dispatched / unknown。丢失响应时不重复派发动作。 |
| 5 | 验收 agent 的完整调用过程 | 从 CLI 发现设备与 App、连接、打开 App，到 observe、读取图片、动作、再观察、结束会话，完成实际调用。先用已有 Fixture 与系统 App 验收，不扩展为通用 App 测试矩阵；产品操作不继承 spike 的 Fixture/Calculator 白名单。 |

第 1 项使用独立的新通信证据，没有借用以前经过 iproxy 的结果。第 2 项在同一条原生链路上实现宿主生命周期：默认值为 1800 秒，实际回收以缩短为 8 秒的真机会话验证，没有等待完整 30 分钟。Runner 在宿主管理模式下不再使用实验的固定 900 秒上限，旧探针模式仍保留该上限。

实现检查应围绕具体风险：原生通信需要真机证据；格式化、引用和计时规则尽量用本地样本与受控条件验证。原有物理重连、锁屏恢复和更广 App/OS 覆盖仍保持较低优先级。

## 实现时收敛的细节

本地 IPC 已采用版本化 JSON 行，一次连接承载一条请求 / 响应；ArgumentParser 已锁定 1.5.0。当前生命周期命令输出 JSON，open 支持保守的三态结果。剩余工程细节包括设备/App 发现命令、坐标与滑动参数、长文本/stdin、观察输出、AX 预算及引用定位方式。当前 connect 暂需指定已签名的 --xctestrun，Runner 暂沿用探针 App 范围；这两项还不是最终产品接入方式。改变产品边界、引入额外设备工具或提高系统前提时，需要重新对齐。

公开发布前还需确定项目许可证与实际支持的系统范围。当前真机证据来自 macOS 15.0.1、Xcode 16.0、iOS 26.6；免 Xcode 安装及未来完全移除 Runner 均没有因此成为已验证能力。
